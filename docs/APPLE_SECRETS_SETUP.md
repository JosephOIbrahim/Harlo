## Stage 1 — Developer ID Application certificate

Canonical: [`SIGNING.md` § "Generate a Developer ID Application certificate"](./SIGNING.md#1-generate-a-developer-id-application-certificate).

- [ ] **Keychain CSR.** Keychain Access → menu → Certificate Assistant → *Request a Certificate From a Certificate Authority*. Enter your email, leave *CA Email* blank, select **Saved to disk**. Save `CertificateSigningRequest.certSigningRequest`.
- [ ] **Portal request.** <https://developer.apple.com/account> → Certificates, IDs & Profiles → **Certificates** → "+" → choose **Developer ID Application** (NOT "Mac Development", NOT "Apple Development"). Upload the CSR.
- [ ] **Download `.cer`.** Save the issued `developerID_application.cer` to disk.
- [ ] **Install in Keychain.** Double-click the `.cer` → confirm it lands in **login** keychain. It should pair with the private key generated by the CSR.
- [ ] **Verify it's usable for signing:**

  ```sh
  security find-identity -v -p codesigning | grep 'Developer ID Application'
  ```

  Expected output: a line like `1) ABC123... "Developer ID Application: Your Name (233JSS4X69)"`. If empty, the cert isn't paired with its private key — re-import from the same Mac that generated the CSR.

- [ ] **Export `.p12`.** Keychain Access → locate `Developer ID Application: <Name> (233JSS4X69)` → right-click → **Export** → format: *Personal Information Exchange (.p12)* → save as `developer_id.p12` → set a strong password. **Record this password** — it becomes secret #3.

## Stage 4 — Local prep (build the 8 values)

Run from the scratch directory holding `developer_id.p12` and `AuthKey_<KEY_ID>.p8`.

- [ ] **Secret 1 — Team ID.** Literal value:

  ```
  233JSS4X69
  ```

- [ ] **Secret 2 — base64 the `.p12`** (no line wrapping; `base64 -i` on macOS produces a single line which GitHub accepts):

  ```sh
  base64 -i developer_id.p12 | pbcopy
  ```

  Paste into a temp file or hold on clipboard for Stage 5.

- [ ] **Secret 3 — `.p12` password.** The exact string you typed during Keychain export.

- [ ] **Secret 4 — cert identity string.** Get the exact form from:

  ```sh
  security find-identity -v -p codesigning | grep 'Developer ID Application' | sed -E 's/.*"(.*)"/\1/'
  ```

  Expected shape: `Developer ID Application: Joseph Ibrahim (233JSS4X69)`. The string must match Keychain *exactly* — `codesign` does substring match but CI uses it verbatim.

- [ ] **Secrets 5 + 6 — Key ID and Issuer ID.** Copy from the App Store Connect API page (Stage 3).

- [ ] **Secret 7 — `.p8` contents.** Full file including BEGIN/END lines, with the original LF line endings preserved:

  ```sh
  cat AuthKey_<KEY_ID>.p8
  ```

  (Don't open in TextEdit — it may add a BOM or CRLF. Use `cat`, `bat`, or `code -`.)

- [ ] **Secret 8 — random keychain password.** Used only inside the ephemeral CI keychain; never touches Apple:

  ```sh
  python3 -c "import secrets; print(secrets.token_urlsafe(32))"
  ```

## Stage 5 — Load secrets into GitHub

Two routes — pick one. Route B is faster but exposes values to your shell history (clear with `history -c` after).

### Route A — Web UI

- [ ] <https://github.com/JosephOIbrahim/Harlo/settings/secrets/actions>
- [ ] For each of the 8 names below, click **New repository secret** → paste the value from Stage 4 → **Add secret**.

### Route B — `gh secret set`

- [ ] Run one per line, reading values from temp files where the body is multi-line (cert blob, `.p8`). For single-line values, the `<<<` form works.

  ```sh
  gh secret set APPLE_TEAM_ID --body '233JSS4X69'
  gh secret set APPLE_DEVELOPER_CERT_P12 < /tmp/cert.p12.b64
  gh secret set APPLE_DEVELOPER_CERT_PASSWORD <<< '<p12 password>'
  gh secret set APPLE_DEVELOPER_CERT_IDENTITY <<< 'Developer ID Application: Joseph Ibrahim (233JSS4X69)'
  gh secret set APP_STORE_CONNECT_API_KEY_ID <<< '<KEY_ID>'
  gh secret set APP_STORE_CONNECT_ISSUER_ID <<< '<ISSUER_ID>'
  gh secret set APP_STORE_CONNECT_PRIVATE_KEY < AuthKey_<KEY_ID>.p8
  gh secret set APPLE_NOTARY_KEYCHAIN_PASSWORD <<< '<random urlsafe string>'
  ```

  `gh` needs to be in the repo (`cd /Users/rustybeard/Code/Harlo`) or use `--repo JosephOIbrahim/Harlo` on each call.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `find-identity` shows the cert but CI fails "no identity found" | Wrong cert type (e.g., *Apple Development* instead of *Developer ID Application*) | Revoke at portal → restart Stage 1. Only **Developer ID Application** notarizes for Gatekeeper. |
| CI step *Import Developer ID certificate* fails with `errSecAuthFailed` | `.p12` password mismatch — most often a stray trailing newline pasted into secret #3 | Re-set `APPLE_DEVELOPER_CERT_PASSWORD` using the `<<<` heredoc form (strips trailing newline) or via the web UI without a trailing return. |
| `notarytool submit` fails with `Could not read private key` or `Invalid JWT` | `.p8` line-endings mangled — TextEdit / Notepad added CRLF or stripped LF | Re-set secret #7 with `gh secret set APPLE_NOTARY_PRIVATE_KEY < AuthKey_<KEY_ID>.p8` directly from the original Apple download. Never open the `.p8` in a GUI editor. |
| `gh secret set` returns `HTTP 403` | PAT missing `repo` scope, or repo is in an org enforcing SAML SSO that the token hasn't been authorized for | `gh auth refresh -s repo` — and if org-owned, authorize the token at `https://github.com/settings/tokens` per-org SSO row. |
| `gh secret list` shows 7 secrets, not 8 | One `gh secret set` call silently failed (often the multi-line `.p8` via `<<<` instead of `<`) | Diff `gh secret list` against the table at top of this file → re-set the missing one using `<` for file-backed values. |
| Identity string mismatch — CI logs `no identity found: "Developer ID Application: ..."` despite import succeeding | Secret #4 has trailing whitespace or a curly-quote from copy-paste | Re-set using the `sed` command in Stage 4; verify with `gh secret list --json name` then inspect run logs. |

For anything past these, drop into [`SIGNING.md` § Troubleshooting](./SIGNING.md#troubleshooting) — it covers stapler, hardened-runtime entitlement, and notarytool failure modes.
