# Harlo — Architecture & Code Review (2026-06-18)

**Reviewer:** Claude Code (multi-agent workflow: 98 agents, ~4.6M tokens, 10 subsystem
maps → adversarial verification → macOS 27/HealthKit research) with every **critical**
finding re-verified by hand.

**Scope:** full tree — ~18.7K LOC Python, ~1.9K Rust, Swift HealthBridge, 130+ test files.

Findings are tagged **VERIFIED** (code read directly) or **FLAGGED** (static-read pass,
not independently confirmed). A standalone adversarial verification run over the 25
critical/high findings was launched separately; see `§9`.

---

## 1. Bottom line

Harlo is **two systems wearing one name**:

- **System A — the shipping memory core.** Rust hippocampus (1-bit SDR + Hamming XOR),
  semantic encoder, hot/warm tiers, coach projection, session management, exposed via the
  MCP server (`recall/store/coach/patterns/status`). **Genuinely well-built; this is what
  v0.1.0 delivers.**
- **System B — the cognitive architecture.** Motor Cortex (Basal Ganglia gate),
  Inquiry/DMN (S1–S8), Amygdala/escalation reflex pipeline, biometric→motor RED, ActionPlan
  persistence, teardown preemption. Sophisticated and unit-tested **in isolation — but most
  is not wired into any live execution path.**

> **Headline:** a large fraction of the 33 Rules are implemented as *correct modules* but
> are **not enforced in the running system**, because nothing calls them. The green
> 1365-test suite hides this: tests exercise **units** (`route_command()`,
> `validate_biometric()`, `gate()`), never the **integration seams** (the launchd socket,
> the Swift wire, the teardown `synthesis_fn`, the motor invocation). The seams are where
> the bugs live.

This is **fixable** and mostly a wiring problem, not a rewrite.

## 2. What's genuinely excellent

- **Rust hot path honors its constraints end-to-end** — `BitVec<u8,Lsb0>`, XOR +
  `count_ones()`, zero float32/cosine, with a *compile-time* assertion the raw slice is
  `&[u8]` (encoder.rs:240) and a real criterion benchmark.
- **Apoptosis is real** (store.rs:276): physical `DELETE` + `VACUUM`, chunked under SQLite's
  999-param ceiling, boundary-tested across the 900 split.
- **Trace exclusion (Rule 11) enforced at runtime** (verifier.py:102) + compliance grep.
- **Verified-only consolidation gated at the Rust store boundary** (reflex.rs:49).
- **Principled biometric privacy posture** — ADR-0001, the barrier + separate schema +
  isolation grep genuinely keep biometrics out of `elenchus/`/`bridge/`. The consent
  wireframe's non-collapsible latency banner is exactly right.
- **Minimal dependencies, clean PyO3 boundary** — the "simple architectures scaled" thesis
  is actually followed.

## 3. Verified critical issues

| # | Issue | Evidence | Impact |
|---|-------|----------|--------|
| **C1** | **launchd socket activation is miswired (systemd protocol).** `daemon/main.py:69-73` reads `LISTEN_FDS`/`fromfd(3)` — systemd. launchd never sets that, so macOS always falls to the dev branch that `unlink`s + rebinds the socket launchd is holding (`Sockets>HarloCommand`). | Read main.py + plist; research confirms launchd uses `launch_activate_socket`. | **Rule 1 (0W idle) not realized on Mac.** Activation races launchd; the plist "inherits FD via LISTEN_FDS" comment is wrong. |
| **C2** | **Swift↔daemon wire-framing mismatch.** `DaemonWriter.swift` sends `4-byte length prefix + JSON`; the daemon reads until `\n` then `json.loads`. **No length-prefix reader exists.** | Read both; grep `struct.unpack/recv(4)/from_bytes` → none. | **Biometric ingest from the real bridge never parses** → `Invalid JSON`; Swift discards the response, so it fails silently. |
| **C3** | **Biometric `force_red` computed but never persisted.** `_handle_biometric_ingest` returns it in the RPC payload only; `basal_ganglia._check_anchor` reads `session_state["biometric_force_red"]`, which **nothing ever writes.** Tracker is a per-process singleton in a short-lived daemon. | Read router.py:1014 + basal_ganglia.py:69. | **The ADR-0001 biometric→motor RED kill-switch is inert end-to-end.** |
| **C4** | **The cognitive architecture is unreachable live.** Daemon handlers `_handle_execute/_plan/_consent/_modulate/_profile/_mode/_reflexes` are **hardcoded stubs**; teardown gets a **no-op** `_synthesis` (manager.py:379); `escalate()` has **no caller**; motor `gate()`/executor are **never invoked**. | grep + router.py:724-781. | Motor Cortex, DMN/Inquiry (S1–S8), Amygdala reflex pipeline **do not run** in the shipping system. |

**Why CI is green anyway:** every test for these paths bypasses the seam —
`test_biometric_ingest` calls `route_command()` directly; `test_swift_python_wire_format`
checks only the JSON *body* vs the schema, never the socket framing; motor/inquiry tests
call modules directly. **The units are correct; the wires are missing or wrong.**

> **One workflow "critical" overturned:** the claim that the daemon entry point ignores
> `--daemon` is **false** — `macos/launcher.py` (the real `.app` entry) dispatches
> `--daemon → run_socket_activated()`. The pyproject `harlo` console-script is a *separate*
> MCP surface. (Recorded so trust in the rest can be calibrated.)

## 4. High-value findings (FLAGGED — static-read, spot-checked)

**Memory correctness**
- **Cross-encoder SDR incompatibility** (encoder.rs vs semantic_encoder.py): Rust lexical
  n-gram hashing and Python BGE+LSH share the 256-byte layout but **not bit semantics**.
  The daemon/CLI default `ENCODER_TYPE="lexical"` while the **MCP server uses `semantic`** —
  so the two shipping surfaces use different encoders by default; a trace stored via MCP and
  recalled via CLI returns near-random neighbors. Pin one, or unify.
- **`DefaultHasher` is not a stable hash** (encoder.rs:98) → query bits drift across
  toolchains relative to stored SDRs. Pin FNV/xxhash with a fixed key.
- **Recall is O(N) full-table scan into RAM** (query.rs:66) on every call; warm-tier
  semantic recall is a Python per-byte `bin().count('1')` scan — contradicts the
  "sqlite-vec 1-bit matching" claim. The <2ms bench times `xor_search` in isolation only.
- **`federated_recall` score merge is unprincipled** — hot BM25 vs warm `1 - dist/2048`
  (which compresses ~0.92–1.0 because ~80-bit SDRs max near Hamming 160) → warm dominates
  the merged sort. Normalize over realistic max-distance.

**Verification heuristics are bag-of-words** (a credibility risk for the Elenchus thesis)
- Intent preservation (Rule 14) + spec-gaming (Rule 15) = a **20% keyword-overlap ratio**
  (intent.py:136); two **divergent** `_STOP_WORDS` sets; sincerity gate (S8) is naive
  substring matching. **This is where on-device Foundation Models should replace the
  heuristics (see §6).**

**Reflex safety**
- **Amygdala permanent reflexes trigger on broad substrings** (`'critical','risk','agree'…`)
  over flattened text → Rule 7 one-shot permanent reflexes from incidental keyword hits,
  skipping GVR. Three **divergent reflex-hash schemes** coexist.

**Rust durability / latency**
- **Apoptosis is not transactional** (store.rs:205) — crash mid-way leaves dangling edges.
- **Fresh `rusqlite::Connection` per PyO3 call** (lib.rs:21) — fixed latency tax.

**macOS bridge (Phase 5B blockers beyond C1/C2)**
- App-Sandbox + **absolute-path UDS** incompatible → use a **Group Container** (entitlements
  already reference `233JSS4X69.com.harlo.shared`; AnchorStore path contradicts it today).
- **Dignified revocation (ADR-0001 §5) unimplemented** — `AnchorStore.clear()` is dead code;
  uninstall doesn't delete the anchor or `launchctl unload` the bridge.
- `enableBackgroundDelivery` + `HKObserverQuery` background wakeups are iOS/watchOS-oriented;
  unverified for a plain `LSUIElement` Mac agent.

*Full register: 6 critical / 19 high / 32 medium / 30 low. Mediums/lows are mostly dead code,
O(n²) at single-user scale, duplicated `ArcType`/`merkle`, the line-oriented `.usda` parser,
and a hardcoded Windows USD path in `src/usd_bootstrap.py`.*

## 6. HealthKit + macOS 27 integration opportunities

**macOS 27 "Golden Gate"** (WWDC 2026-06-08; dev beta now, GA ~Sept 2026 — *research
confidence: medium, beta APIs*). Apple-Silicon-only.

### The transformative one: Apple Foundation Models as a *local* reasoning provider
Apple shipped an official **Python SDK** (`pip install apple-fm-sdk`) over the on-device
model behind Apple Intelligence: on-device ~3B model (8K context as of 26.4), **guided
generation** + **tool calling**, plus a Private Cloud Compute tier (32K, reasoning) and a
reported local `fm serve` OpenAI-compatible endpoint.

- Add `provider/apple_fm.py` (drops into the existing provider abstraction). **[scaffolded
  in this branch]**
- **Replace the brittle bag-of-words verifiers** (intent, spec-gaming, sincerity S8) with
  on-device guided-generation judgments — no cloud, no trace leakage, Rule 11-safe.
- Small context suits these bounded classification tasks, not full reasoning.
- **Effort L, payoff transformative** — extends "all state local" to "sensitive cognition local."

### macOS 27 platform surfaces
- **Daemon registration:** move to `SMAppService.daemon` + proper `launch_activate_socket`
  (fixes C1). `BGTaskScheduler` is **not** on native macOS; `NSBackgroundActivityScheduler`
  is the in-app option.
- **The missing Rule 18 Recovery menu:** menu-bar item + interactive UserNotifications + a
  Control Center Control (App Intents). **NOT Live Activities** (not native on Mac). The
  recovery action **must not** be a Basal-Ganglia-gated motor action (under RED the gate
  inhibits it; exempting it breaks "RED overrides everything") — split into a motor plane
  (stays locked) and a modulation/UI plane (`recovery_ack`).
- **App Intents are now mandatory for Siri** (SiriKit deprecated) + a Spotlight semantic
  index — surface only the derived `cognitive_state` enum, never raw HR; disable
  intent-parameter donation that could persist a value.
- **HealthKit on Mac is framework-only** (no native Health app in 27) — the sync-latency UX
  framing stays correct.

## 10. Adversarial verification results (2026-06-18)

A standalone 26-agent verification run re-checked the 25 critical/high findings against the
real code (refute-by-default). **21 confirmed real, 4 overturned.**

**Confirmed criticals/highs (selected):**
- **CRITICAL #0** cross-encoder SDR incompatibility — *worse than first framed*: the MCP
  `store` + Observer promotion write **semantic** bits into the shared `traces` table while
  the daemon recall defaults to **lexical** (`ENCODER_TYPE="lexical"`), so mixing is the
  **deployed default**, silently returning near-random neighbors.
- **CRITICAL #20** Swift↔daemon wire framing — *fixed in this branch (C2)*.
- **HIGH #12** launchd systemd-protocol mismatch — *fixed (C1)*.
- **HIGH #8/#16** biometric `force_red` never persisted — *fixed (C3)*.
- **HIGH #5** `run_gvr(stage, resolution, depth_config)` passes positional args that
  misalign with the signature → the daemon GVR path is dead on arrival.
- **HIGH #6** DMN synthesis is a no-op (`_synthesis(ctx)→ctx`); **HIGH #7** inquiry state has
  no persistence; **HIGH #3** amygdala substring triggers; **HIGH #17/#18** federated_recall
  scoring bugs.

**Overturned (recorded for honesty):**
- **#13** pyproject entry point — the `launcher.py` shim handles `--daemon`; refuted (matches
  the §3 note).
- **#10** Rule 27 consent downgrade — implements the rule exactly as narrowly written.
- **#15** "daemon serves one connection" — intentional under socket activation, not a bug.
- **#19** warm-tier O(n) scan — literally true but a deliberate single-user-scale tradeoff.

**Severity recalibrations:** #1 DefaultHasher critical→medium (low near-term probability);
#9 allostatic config-lie high→low; #4 intent keyword-overlap high→low; #11/#14 →lower.

Remaining confirmed criticals not yet fixed (P1/C4 scope): #0 cross-encoder, #5 run_gvr,
#6 DMN no-op, #7 inquiry persistence, #3 amygdala triggers, #17/#18 federated scoring.
